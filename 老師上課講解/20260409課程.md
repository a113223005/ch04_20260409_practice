# 課程主題：AI Agent 智慧 App 產品設計 —— 天下茶屋專案實務

## 觀念導讀：用 AI Agent 規格書蓋出一個 App

> 在本次實作中，我們要開發的是一套具備實務運作邏輯的 **「智慧點餐 App」**。
>
> 您的目標是設計出這套 App 的 **「產品大腦」**：
> * 它要能 **執行任務**（例如：下單、查帳）。
> * 它要能 **處理商業邏輯**（例如：打折、計算運費）。
> * 它要能 **精準計算與攔截錯誤**（例如：防止不合適的點餐組合）。

---

## 1. 專案背景：天下茶屋 (Tenka Tea) 智慧點餐 App 開發計畫

「天下茶屋」位處技術密集型的高科技辦公園區。為了維持品牌傳承的品質標準並提升效率，全店決定導入智慧點餐 App。這套 App 必須承載店內的業務規則與產品定價數據。

## 單元一：產品開發實務階段 (Planning)

### 概念破冰：這 5 個組件，就是 App 的程式結構

> 對新手來說，最重要的一件事：**你寫的這些 Markdown 文件，就是 App 的規格書。**  
> AI 讀取你的規格書，幫你把 App 蓋出來。

| 組件名稱 | 對應的程式概念 | 在 App 裡的實際作用 |
| :--- | :--- | :--- |
| **Persona** | UI 語氣 / 品牌設定 | 決定 App 跟用戶說話的方式與風格 |
| **Rules** | `if / else` 商業邏輯 | 攔截不合規的操作（例：熱飲禁止加珍珠） |
| **Workflows** | 操作流程 / Pipeline | 規定 App 一步步怎麼引導用戶完成任務 |
| **Skills** | `function()` 功能模組 | App 的運算核心（算錢、積點、折扣） |
| **Knowledge** | 資料庫 / Database | 所有品項、定價、事實數據的唯一來源 |

## 單元三：重點回顧測驗 (Q1 ~ Q6)

- **Q1：Persona 檔案建議存放的位置為何？**  
  正確解答：存放在隱藏目錄 `.agent/` 及其子目錄下。

- **Q2：Agent 開發者的核心價值是什麼？**  
  正確解答：負責「核心規則」與「商業架構」的規劃。

- **Q3：Agent 去哪裡得知產品的單價與清單？**  
  正確解答：去 **系統知識庫 (Knowledge)** 組件或個案白皮書中索引事實數據。

- **Q4：若系統需導入「天下茶屋三週年 8 折優惠」，下列哪些組件需要參與定義？（複選）**

  - A. Persona — 定義服務語氣與品牌風格
  - B. Knowledge — 存放促銷碼與折扣率數據
  - C. Skills — 定義套用折扣的計算邏輯
  - D. Workflows — 定義結帳的執行流程

  **正確解答：B + C**

  > **解析**：這題考的是「數據」與「邏輯」的分工。
  > * 促銷碼 `TENKA_80` 和折扣率 `0.8` 是業務事實數據，屬於 **Knowledge** 的責任——它是所有運算的「事實來源」。
  > * 「當促銷碼匹配時，將總額乘以 0.8」的計算規則，才是 **Skills** 的責任——它定義「怎麼算」。
  > * 兩者分工：**Knowledge 說「是什麼」，Skills 說「怎麼做」**。若把數據寫死在 Skills 裡，日後促銷活動一變動就要改程式邏輯，這是常見的設計錯誤。

- **Q5：為什麼在 Markdown 標題 (#) 下方一定要留一行空行？**  
  正確解析：為了符合 MD022 規範，確保系統解析精準度。

- **Q6：當產品功能變多時，為什麼要用子資料夾分類？**  
  正確解析：實現「邏輯解耦」，方便獨立維護各項模組。
