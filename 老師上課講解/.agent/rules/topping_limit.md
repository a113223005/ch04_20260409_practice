# 業務規則：熱飲加配料之品質攔截 (Topping Logic)

## 1. 基礎實作規劃 (攔截敘述：小白版)

本項規則展示了如何透過系統強制執行天下茶屋的品質標準：

### 核心禁令描述
* **條件**：當用戶選擇「熱 (Hot)」飲品項。
* **限制**：一律不允許加入「珍珠 (Boba)」。
* **理由**：珍珠在熱飲中會軟化過快，損害口感，這是天下茶屋的工藝堅持。

### 回報訊息範例
* 系統攔截時提示：「很抱歉！為了維持珍珠品質，天下茶屋不提供熱飲加珍珠的選擇，建議您改選溫飲或冷飲。」

---

## 2. 進階實作規格 (規則表：進階版)

為確保邏輯精確定，定義下列數據攔截矩陣：

### 營運邏輯對照表 (Validation Matrix)

| 溫度屬性 (Temp_Attr) | 配料屬性 (Topping_Attr) | 結帳狀態 | 指令碼 (Action) |
| :--- | :--- | :--- | :--- |
| **熱 (Hot)** | 珍珠 (Boba) | 攔截 | `REFUSE_ADDON` |
| **熱 (Hot)** | 椰果 (Jelly) | 允許 | `ALLOW` |
| **溫 (Warm)** | 珍珠 (Boba) | 允許 | `ALLOW` |
| **冰 (Cold)** | 不限 | 允許 | `ALLOW` |
